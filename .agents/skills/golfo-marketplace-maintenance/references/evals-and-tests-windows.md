# Evals y tests en Windows

Leer antes de correr bats o `run-evals` de golfo-kit en esta máquina, o al escribir casos de `eval-config.json`.

## Correr suites y evals

- bats no está en el PATH de Git Bash: correlo con `LC_ALL=C.UTF-8 bash scripts/run-bats.sh <suite>` desde la raíz del repo (con el arreglo de variables MSYS de `windows-git-bash-agent-gotchas` si el agente las exporta). Desde Hermes, la forma que anda es: `LC_ALL=C.UTF-8 env -u MSYS_NO_PATHCONV -u MSYS2_ARG_CONV_EXCL TMPDIR="$(cygpath -m "$LOCALAPPDATA/Temp")" bash scripts/run-bats.sh <suite>`. No uses `pnpm exec bats`: el shim de pnpm arranca bats por su ruta `C:\`, y la trampa `DEBUG` de bats abre entonces un subshell por cada comando de su librería, casi 3 minutos por corrida filtrada de `bootstrap.bats` (#95, PR #166).
- Claude Code corta los procesos en background cuando falta memoria. Un bats lanzado en foreground también pasa a background al superar los 10 minutos, y ahí queda expuesto al mismo corte. Las suites de agent-ready-setup (`bootstrap.bats`, `merge-instructions.bats`) tardan más que eso enteras. Cada test lleva un tag de área (`# bats test_tags=area:<área>`) y cada área suma menos de 5 minutos: corré la del cambio con `--filter-tags area:<área>` (tabla en «Áreas de `bootstrap.bats` y `merge-instructions.bats`» del README) y dejá la suite entera al CI. Con poca RAM no reintentes en local lo que se cortó: aclaralo en las notas del PR.
- Un test que corre bats adentro (como `tests/run-bats.bats`) tiene que sacarle `BATS_TEST_TIMEOUT` al bats anidado (`env -u BATS_TEST_TIMEOUT`): en Git Bash el watchdog del timeout sobrevive al test y `run` espera a que cierre la salida, hasta el timeout entero.
- El test «without the timeout executable a slow GitHub call is still cut at the budget» de `wait-for-pr-event.bats` es flaky por timing en una máquina Windows cargada: reintentarlo antes de culpar al cambio.
- Si algún `input` de evals empieza con `/` (p. ej. `/be-ambitious ...`), NO saques las variables MSYS: con `env -u MSYS_NO_PATHCONV -u MSYS2_ARG_CONV_EXCL`, Git Bash convierte el argumento que recibe `claude.exe` en un path (`C:/.../git-.../be-ambitious ...`) y las evals pasan con un input que el modelo nunca vio. Correlas con `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'` y verificá el campo `input` del JSONL.
- `run-evals` necesita paths `C:/...` (jq no resuelve `/tmp`; el agente de evals tampoco encuentra `SKILL.md` bajo `/tmp`) y pierde la línea JSONL de un caso cuya assertion fallida tiene texto no ASCII. El provider Codex falla el preflight en Windows: correr las evals con el provider Claude.
- `run-evals` (`skill-eval-runner/run-evals.sh <skill-dir>`) no filtra por caso: corre todos los de la skill (agent-ready-setup tiene más de 50, unos 7 min). Para saber si una falla es tuya, mirá los `.eval-results/<skill>/case-results-*/N.failures` no vacíos y su `case_id` en `N.jsonl`; las salidas por caso están en `with-skill/<case-id>.txt`. Borrá `.eval-results/` antes de commitear: queda en el cwd, y si corrés sobre una copia o un worktree hermano también aparece en el checkout principal del repo. Para correr un solo caso, copiá la skill entera a un dir `C:/...` del scratch, filtrá el array de casos de esa copia de `eval-config.json` por `id` (mirá antes cuál es la clave del array: si filtrás una clave inexistente el runner corre todos igual) y pasale ese dir al runner.
- Desde Claude Code (exporta `MSYS_NO_PATHCONV=1`), el runner arma la vista aislada de la skill con `mktemp` + `pwd -P` y el agente recibe `/tmp/tmp.X/...`, que no abre: todas las respuestas dicen «no pude leer el contrato». Arreglo: copia local del runner con `pwd -W` en `create_isolated_skill_view`, fuera de `%LOCALAPPDATA%\Temp`, corrida con `env -u MSYS_NO_PATHCONV -u MSYS2_ARG_CONV_EXCL`. `--config` falla igual («Invalid eval-config.json», jq nativo con `/c/...`): copiar el plugin y reemplazar el `eval-config.json` de la copia. Cada copia del runner en su dir tiene su `.eval-results`, así baseline y candidato corren en paralelo.
- Evals inválidas se delatan por una corrida muy rápida o respuestas sin lecturas: leer una respuesta `with-skill` antes de confiar en el pass rate.
- `scripts/run_eval.py` (trigger evals) de skill-creator usa `select.select` sobre pipes: no corre en Windows; la activación queda como hallazgo abierto.
- Desde #170 el runner aísla la skill (el agente evaluado solo lee su cwd y la copia): las evals de un PR viejo se repiten con el runner de `origin/main`, porque antes podía leer la skill instalada y pasar por eso. jq nativo no abre `/c/...`: pasale el archivo por stdin (`jq ... < archivo`). Probar las regex de assertions desde bash, no desde un `subprocess` de Python: el grep de MSYS expande las llaves (`{0,120}`). `TaskStop` sobre un `run-evals` en background deja huérfanos los bash y `claude.exe` hijos: matarlos por la ruta de la copia y confirmar con `Win32_Process`.
- `quick_validate` de `skill-creator` rechaza `agent-ready-setup` por los `SKILL.md` de templates anidados en `assets/`: es preexistente, no bloquea.
- Para separar regresiones de fallos que ya estaban, correr el baseline de `origin/main` (`git archive origin/main plugins/golfo-kit` a un directorio temporal). `run-evals` guarda resultados por nombre de skill en `~/.local/.eval-results/<skill>`: copiarlos antes del baseline o se pisan. Varios casos de `measured-performance-optimization` y `nextjs-route-ui-boundaries` ya fallan en main por assertions de redacción estrictas.

## Escribir casos y assertions

- Una assertion `contains_any` con palabras que ya trae el `input` del caso (p. ej. «diseño») pasa siempre: usar términos que solo aparecen si el modelo aplicó la regla.
- Las assertions `contains_any` se evalúan con `grep -qi`: cada valor es una regex sin distinguir mayúsculas. Revisar que ningún valor aparezca en el input, cualquiera sea su capitalización.
- Ese `grep` es BRE, sin `-E`: `{n,m}`, `+` y `|` sin escapar son literales y la assertion nunca matchea. Usar `.*` o clases (`[+]`) en vez de cuantificadores.
- Una assertion con el nombre de otra skill no discrimina: la versión vieja la nombra sin cargarla. Chequear algo que solo aparece al aplicarla (su kit, el carácter que fija).
- Un input que dice «Implementalo» sin código da respuestas de solo plan y fallos léxicos flaky: correr 4+ repeticiones pareadas contra `origin/main` antes de llamar regresión a una diferencia.
- Para sumar un caso a `eval-config.json`, insertarlo como texto después del último caso, con la misma indentación. Un `json.dumps` del archivo entero lo reformatea y deja un diff de cientos de líneas.
- Las regex de evals con barras invertidas se rompen al escribirlas por heredoc o `node -e`: escribir el JSON con una herramienta de escritura de archivos, o evitar escapes (`[+]` en vez de `\+`).
