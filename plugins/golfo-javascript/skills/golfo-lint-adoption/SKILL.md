# Adopt golfo-lint in a repo (and fix golfo-lint along the way)

Install @golfo/lint in a consumer repo, fix what it reports and gate it in CI. Applies to any golfo project (TuTribu, agenda-mensual, golfo-*). The package source is the golfo-lint repo (`guidomodarelli/golfo-lint`, usually cloned at `~/ghq/projects/golfo-lint`; README = source of truth for options and subcommands; its AGENTS.md has the rule-selection policy).

## Standing user preferences (apply to every step)

- Only real defects; everything is an error; no disable comments; no formatting or equivalent-spelling rules.
- **No false positives, no duplicated findings, no empty reports.** A report that flags valid code, repeats another rule/tool, or "passes" because the tool silently analyzed nothing is a golfo-lint bug. Fix it in golfo-lint (wrap/filter/turn off the rule, with a comment saying why or which rule stays), never with disables in the consumer.
- **Iterate**: change golfo-lint → rerun on the consumer → sample findings again → repeat until what remains is real. Then release golfo-lint and fix the consumer.
- When the user says "arreglá todo", that means the whole scope: golfo-lint fixes + every consumer finding + CI + PR. Do not re-ask scope; split the consumer fixes into parallel subagents/PRs by tool or folder instead.
- **Label every timing you report** with what ran (runner, rule set, threads) and why: a number from an auxiliary run (ground-truth ESLint with one rule, a benchmark of a rejected option) reads as a regression of the real runner unless you say so next to the current runner's time.
- **Report progress unprompted, without stopping.** This job runs for hours and only a turn's final message reaches the chat, so text between tool calls is never seen. At the start, set up a recurring progress notice with whatever the agent offers (a status file plus a scheduled notice in Hermes chat gateways, `PushNotification` or short status lines in Claude Code), then update it at each milestone (Codex round processed, subagent batch finished, suite result, commit) with numbers (findings before/after, what is running, what is next) and keep working. A notice is just a notice: never end the turn only to report.
- **The user considers a ~5 min full ESLint run too slow** and wants golfo-lint's rule set trimmed where rules cost time without finding defects. Bring measured per-rule/per-plugin cost and finding counts, propose concrete cuts in the preset, and verify the saving — do not answer with "it's typed linting, nothing to do".
- **Keep the job fast; the user notices.** Iterate on ESLint with the cache or only on the files you touched (`eslint <files>`), never a full 6–12 min run per iteration; keep the full run for final validation. Cap Codex review rounds on golfo-lint PRs: when the cap is hit (or the user says "mergeá"), merge with green CI and move remaining findings to a follow-up issue, replying in each thread with the issue link, instead of chasing edge cases round after round.
- **Never delete deployment-target adaptations** (OpenNext/Cloudflare Workers: `open-next.config.ts`, `wrangler.jsonc`, `cloudflare/`, output-tracing configs, `pg-cloudflare`) or other runtime-only pieces because knip/dependency-cruiser calls them unused: they are loaded by the platform at build/run time. Resolve with `knip.config.js` (`createKnipConfig({ entry, ignoreDependencies, ignoreBinaries })`) and tell subagents so in their brief.

## Procedure

1. **Isolate.** Never work on the primary checkout's default branch. Worktrees for both repos from fresh remote bases:
   `git fetch origin && git worktree add -b feature/golfo-lint ../<Repo>-worktrees/golfo-lint origin/main` (copy `.env*` from the primary checkout), and the same for golfo-lint under `../golfo-lint-worktrees/<slug>` (`npm ci` there).
2. **Install exact versions** in the consumer: `pnpm add -D --save-exact @golfo/lint@<latest> eslint react-doctor@<version in golfo-lint README>` (react-doctor only with React). pnpm 12: `allowBuilds.unrs-resolver: true` must exist in `pnpm-workspace.yaml`; add a freshly published `@golfo/*` to `minimumReleaseAgeExclude` **by name only** (`"@golfo/lint"`, like the other golfo packages) if `minimumReleaseAge` blocks it — a versioned entry (`'@golfo/lint@0.2.1'`) blocks the next bump, because the lockfile still holds the old version while pnpm re-verifies it.
3. **Config.** `eslint.config.mjs` with `createEslintConfig({ tsconfigRootDir: import.meta.dirname, react, next, vitest })` (add `linter: "bun"` when it runs through `bun lint`; typed custom rules then run as the native rule plus golfo-lint's post-filter — see [references/fast-linter-runners.md](references/fast-linter-runners.md)). Pass `tsconfigFiles` if the test tsconfig is not `tsconfig.test.json`, or ESLint takes hours.
4. **Inventory.** Each analysis to its own file, record exit code + count:
   `for c in styles duplicates unused architecture workflows secrets react; do pnpm exec golfo-lint $c > $TMPDIR/gl/$c.txt 2>&1; echo "$c exit $?"; done`
   ESLint apart, in background, JSON output (~8–12 min on ~200k LOC; `--concurrency 4` cut it ~30%): `NODE_OPTIONS=--max-old-space-size=8192 pnpm exec eslint . -f json -o C:/.../gl/eslint.json`. Aggregate per rule AND co-located rule pairs (same file:line:col) with a script — pairs expose duplicated rules.
5. **Triage every rule with real samples** (3–6 source lines per rule, split prod/tests). Classify: real defect / false positive / style / duplicate / advice-not-defect / tool bug. Decision table and known classes: [references/false-positive-triage.md](references/false-positive-triage.md).
6. **Fix golfo-lint** and test it against the consumer *before* releasing (recipe in the reference: dev ESLint config importing the worktree by `file:///` URL, and `node <worktree>/bin/golfo-lint.js <cmd>` run from the consumer). Add a test per fix (fixtures under `test/fixtures`, temp projects in tests), update README/CHANGELOG/AGENTS.md, run `npm run ci`, `node bin/golfo-lint.js all`, `npm run check:packed-install`. PR → merge → `npm run create-version` (see `golfo-npm-package-release`).
7. **Consumer**: bump to the released version, delete the dev config, then fix by tool, smallest-risk first (workflow pinning, stylelint, knip config entries for real entry points, react-doctor, ESLint autofix, then the rest), running the repo's `ci` script after each batch.
   - **Autofix pass**: run `eslint --fix` with a throwaway config that spreads the preset and turns off fixers that change behavior or leave junk — `@typescript-eslint/no-unnecessary-boolean-literal-compare` (`x !== false` → `x` flips a defensive check when external data is typed `boolean`) and `@typescript-eslint/no-meaningless-void-operator` (`void x;` → bare `x;`). Those `void x;` statements almost always exist only to silence `no-unused-vars` (`async (...args) => { void args; … }` in mocks, `({ kind, ...rest }) => { void kind; … }`): the preset's `no-unused-vars` ignores rest siblings and `_`-prefixed params, so remove them with a `typescript` AST codemod over the lint JSON — delete the statement and rename the parameter to `_x` when that statement was its only use; never let the fixer leave a bare `x;`. Then run `typecheck` + `typecheck:tests` and the test suite. If the fix broke compilation, fix the fixer in golfo-lint, revert only source files (`git diff --name-only | grep -E '\.(ts|tsx|js|mjs)$' | xargs git checkout --`, keeping CSS/YAML edits) and rerun. Commit the autofix as its own checkpoint.
   - **Manual fixes in parallel**: partition the remaining ESLint files by folder into lists (~80–150 files each), write one shared brief file (rules: shared worktree → edit only your list, no git stash/checkout/reset/commit/install; no behavior change; no disables or workarounds; report suspected golfo-lint false positives as file:line + rule + reason instead of contorting code; validate with ESLint on the list, both tsc configs filtered to own files, related vitest), and spawn subagents pointing at brief + list. Make each brief require the full final report (before/after counts, tests, every suspected false positive as file:line rule — why) to be written to `<workspace>/<task>-report.md` as well as returned: background results can fail to reach the parent and live transcripts truncate long messages (in Hermes, `~/AppData/Local/hermes/cache/delegation/live/<id>/task-N.log`, status in `manifest.json`). If a finished child's result never arrives, read that file (or the child's engram save) instead of waiting. Launch at most ~4 at once: each typed ESLint run builds the whole TS program (3–5 GB). Feed reported false positives back into step 6 only after checking each one yourself against the code: subagents label runtime guards, intentional `||` and deliberate deprecated APIs as false positives in bulk, and some are real defects to fix in the consumer.
   - **Too many findings for one PR**: offer three options and let the user pick — (a) open the PR now and fix per module in follow-ups, (b) drive everything to zero here (hours), (c) turn off in the consumer the rules with most findings and re-enable them one per PR. For (c): count findings per rule from the ESLint JSON, put every rule with ≥30 findings in a `RULES_PENDING_ADOPTION` array in `eslint.config.mjs`, spread after the preset as `{ name: "<repo>/rules-pending-adoption", rules: Object.fromEntries(list.map((r) => [r, "off"])) }` with a JSDoc saying each rule leaves the list in its own PR and new rules are never added; then split only the remaining findings by folder (tests/modules, other tests, product code) across subagents with the brief rules below.
   - **Evaluating the pending list** ("evaluá si valen la pena"): run the linter once with the pending block removed (throwaway config), then per rule count prod vs tests, and read 5 random sampled lines (`random.seed`, real source line per finding). Decide per rule: keep and fix in the consumer (real defect or readability: nested ternaries, deprecated APIs, `!`, long/complex/deep functions, bare `toThrow()`); turn off in the preset's `NON_DEFECT_RULES` when most samples are valid code (`prefer-nullish-coalescing` on intentional `|| ""/0` fallbacks, `vitest/no-conditional-expect` in parametrized/browser tests); relax only in `createTestFilesConfig` when the findings concentrate in tests (fixture helpers with many params, `String(init?.body)`, rethrows). Then delete the pending block entirely, rerun, bin-pack the remaining files by area into ≤8 balanced lists and dispatch subagents. Report the per-rule verdict table to the user.
   - **`no-unnecessary-condition` brief for subagents** (it is usually the largest bucket): per report decide (1) type right and check redundant → remove the check/fallback; (2) type lies because the value can really be missing (external JSON, DB rows, `Record` index, `array[i]`, env, values set in `beforeAll`/callbacks) → widen the type and keep the check, never delete defenses on external data; (3) narrowing TS cannot see (flag flipped in a cleanup, property re-read after `await`) → restructure without behavior change, keep the check. Assign every rule's findings in a file to the subagent owning that file, so no two agents edit one file.
   - **After each subagent batch, run the repo's existing linter too** (e.g. `pnpm run lint` with oxlint): refactors for the preset leave unused imports, new magic numbers or impure calls in render that only the other linter reports.
   - **Existing linters**: never remove the repo's linter on your own. While the preset runs on ESLint next to it, add it as a separate script/CI step (`lint:eslint`). When the user moves the preset to a faster runner (`bun lint`), that runner becomes the repo's `lint` script and replaces the old linter, its config and the ESLint script/CI steps.
   - **Consumer-owned rules move into golfo-lint**: rules the consumer turned off or added itself (custom JS plugins such as a no-disable-comments plugin, extra options of preset rules like `enforceConst`, architecture boundaries like "layers never import `setup.ts`") go into the preset or the dependency-cruiser hexagonal rules when they are generic. Keep in the consumer only project paths/packages that would be false positives elsewhere (e.g. its own UI package boundaries), and delete restrictions on paths that no longer exist. Check each moved rule on the consumer before reporting.
8. **CI.** Add a separate `golfo-lint` job to the quality-gate workflow and list it in the final gate job's `needs` and result check. Reuse the repo's setup action, install `uv` for actionlint/zizmor and `gitleaks` with checksum, and pin every new action by SHA (verify with `golfo-lint workflows`). Run ESLint through a script, not inline: `"lint:eslint": "eslint . --concurrency auto --cache --cache-location node_modules/.cache/eslint/ --cache-strategy content"`, then `pnpm exec golfo-lint all`. Keep the repo's `ci` script and workflow in sync when it documents that contract. With the `bun lint` runner, `golfo-lint all` already runs `golfo-lint lint`: drop the separate Lint step (and the ESLint script and cache steps) instead of linting twice, and say in a workflow comment where lint runs.
   - **No restored ESLint cache in the PR gate**: never restore ESLint result caches (`actions/cache/restore`) for the typed check of a pull request. ESLint's cache does not track dependencies between files, so when a PR changes an exported type without touching its importers, those files reuse their clean results from `main` and the error only shows after merge. Run the CI step without a restored cache (the `lint:eslint` script with a fresh `--cache-location` under `$RUNNER_TEMP`, or without `--cache`) and keep `--cache` for local iteration. To make the gate faster, use the options in the next bullet (concurrency, per-rule cuts, `bun lint`) instead of a cache.
   - **When ESLint is slow, offer options cheapest-first and let the user pick**: (1) concurrency (plus `--cache` only for local runs, see the previous bullet), (2) measure with `TIMING=60 eslint ... --stats -f json` in a single thread so per-rule times are accurate (~12 min on 200k LOC; run it in background) and turn off, **in the golfo-lint preset (not the consumer)**, heavy rules that cannot report anything in the project or whose findings are false positives/duplicates. Known heavy ones: `sonarjs/aws-*` (~10%, only meaningful with `aws-cdk-lib` → gated behind an opt-in preset option like `react`/`next`/`vitest`), `sonarjs/no-redundant-assignments` (~7%), `import-x/no-cycle` (dependency-cruiser covers it). For a cost/value view, aggregate the `--stats` JSON (`stats.times.passes[].rules.<rule>.total`, ms) per plugin and join each rule with its finding count from a full ESLint JSON: on a 200k LOC Next repo sonarjs took ~46% of rule time while only ~24 of its ~207 rules ever reported anything, typescript-eslint ~28%, unicorn ~13% (most of it in zero-finding rules). knip, dependency-cruiser and jscpd are separate golfo-lint commands, never part of ESLint time — say so when the user blames them.
   - **Prove a cut with a wall-clock A/B before changing the preset**: typed rules (typescript-eslint and many sonarjs rules) share the lazily-computed TS checker, so the first typed rule on a file absorbs that cost and turning it off can just move the time to the next one. Write a throwaway `eslint.speed.config.mjs` that spreads `./eslint.config.mjs` and turns off the candidate set, then run it and the real config back to back with the same `--concurrency` on a quiet machine (not while subagents lint). Under pnpm the plugin is not resolvable from the consumer root: load it through the preset with `createRequire(createRequire(import.meta.url).resolve("@golfo/lint/package.json"))("eslint-plugin-sonarjs")`; check the config imports (`node.exe -e "import('./eslint.speed.config.mjs')..."`) before launching a 5-minute run. Before calling a rule a duplicate, count its findings in the ESLint JSON and read them — a rule that only resembles another is not a duplicate; justify turning it off with its real findings, (3) run the preset with **`bun lint`** (adopted): it reads the ESLint config as is, runs natively what it implements (typed rules on TypeScript 7) and the rest as JS plugins — ~5× faster than ESLint with the same findings. An oxlint config generated from the preset (and an oxlint+ESLint hybrid) were tried and dropped: slower than `bun lint` and they lost rules in the conversion; do not leave hybrid or throwaway runner configs behind. Recipe, pitfalls and reference timings: [references/fast-linter-runners.md](references/fast-linter-runners.md). Do not switch runners without approval.
9. **Gate on `golfo-lint all`, not only `lint`.** Before calling the consumer clean, run `pnpm exec golfo-lint all` with the *published* version and record each analysis' exit. Refactor batches (function splits, parameter objects, extracted hooks) create new unused exports, import cycles and clones that only knip, dependency-cruiser and jscpd see, so rerun `all` after each batch, not just at the end. If the CI job running `all` is new in this PR and several analyses fail with large counts, offer: (a) gate only the analyses that pass now and enable each remaining one in its own PR, (b) fix everything here, (c) as (a) plus a temporary higher consumer threshold for duplicates. For (a): run each candidate locally first and keep only those exiting 0; in the job use `set -euo pipefail; for analysis in lint styles workflows secrets; do pnpm exec golfo-lint "$analysis"; done`; open one tracking issue with a checkbox per failing analysis (count, top rule/area, and any "configure, don't delete" note such as `pg-cloudflare` in knip) and link it from the workflow comment, which also says the step becomes `golfo-lint all` once the list is empty. Update AGENTS.md/README lines that said lint runs "inside `golfo-lint all`".
10. When the user asked to publish, or the agent's global rules say changes ship on their own, close out with commit, push and PR (`pr-description-template`) and launch `codex-autofix-loop`, both from plugin `golfo-github`. Otherwise, and always when `~/.work` exists on the machine unless the user asks to publish, leave the changes uncommitted and list them instead (see «Cierres que publican» in [`work-machine-gate.md`](../../references/work-machine-gate.md)).

## Fixes that belong in a shared library

When the right fix for a consumer finding is in another golfo package (e.g. a disabled control that must stay focusable lives in `@golfo/ui`'s component), fix it there instead of contorting the consumer: worktree in that repo, failing test first, CHANGELOG `[Unreleased]` entry, its full `check`/tests, and real-browser Playwright coverage for any styling or interaction change (Codex asks for it when jsdom is the only coverage; `click({ force: true })` is needed on `aria-disabled` controls because Playwright waits for them to be enabled). PR with `pr-description-template`, merge with the repo's allowed strategy, release with its `create-version --ci --<bump>`, then bump the consumer and update its tests that asserted the old behavior (`toBeDisabled()` → `toHaveAttribute("aria-disabled", "true")`).

## Pitfalls

Known traps (subagent batches, typed rules, git-bash paths, CI, gitleaks, stylelint, dependency-cruiser, knip, jscpd, react-doctor, runner switches and consumer false positives): [references/pitfalls.md](references/pitfalls.md). Read it before step 4 and again before steps 7 and 8.
