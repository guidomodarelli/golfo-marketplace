# Triage of golfo-lint findings: decision table, known classes, test recipe

## Decision table

| Finding looks like | Action in golfo-lint |
| --- | --- |
| Chooses between equivalent spellings or depends on layout (`[...x].sort()` vs `toSorted()`, nested templates, braceless one-liners, `expect(a===b).toBe(true)`, longhand vs shorthand CSS) | `STYLISTIC_SUGGESTION_RULES` (ESLint) / remove from stylelint config |
| Same problem reported by another rule or tool | `DUPLICATED_RULES` with a comment naming the rule that stays; prefer the typed rule, the tool that owns the domain (gitleaks for secrets, zizmor for workflows, knip for unlisted deps) |
| Flags valid code by design (security hotspots "make sure X is safe", advice that assumes independence, correct patterns it forbids) | `NON_DEFECT_RULES` / react-doctor exclusion list |
| Rule is right in general but has a mechanical FP class | Wrap or filter it (ESLint rule wrapper in `src/eslint/rules/`, react-doctor JSON filter, gitleaks allowlist with `condition = "AND"` + `targetRules`) |
| Tool cannot parse new syntax / uses wrong dependency | Preprocess input or redirect resolution; never drop the check |
| Only fine in tests | Relax in `createTestFilesConfig` |

Always sample real lines before deciding; counts alone hide FP classes.

## Known FP classes and their fixes

- **`no-unnecessary-condition`**: TypeScript keeps property narrowing across `await`/calls (`signal.aborted`, `ref.current`); without `noUncheckedIndexedAccess`, array elements and record entries look always present (also through variables `const first = items[0]`, `const [first] = items`, and chains `target?.id ?? ''`); a `let` reassigned inside a callback or cleanup keeps its narrowed type (`let found = false; arr.forEach(() => { found = true }); if (found)`); host globals are feature detection (`globalThis.crypto?.randomUUID`, `if (!Element.prototype.scrollIntoView)`). golfo-lint wraps the rule (`golfo-lint/no-unnecessary-condition`): declared vs flow type differs on a property or a `let`/`var` → drop; a root identifier with **some** declaration in a TypeScript `lib` file (`program.isSourceFileDefaultLibrary`) → drop (use `some`, not `every`: `@types/react` merges an empty global `Element`); walk the whole member/call chain; check both operands of `noOverlapBooleanExpression`. Check `let`/`var` via the list's first token kind, not `flags & NodeFlags.Const` (sonarjs bitwise rule).
- **Rules that contradict each other**: `unicorn/no-useless-switch-case` asks to delete the `case X: default:` that `switch-exhaustiveness-check` requires → off in TS. Sort: keep `@typescript-eslint/require-array-sort-compare` (`ignoreStringArrays`) in typed TS and turn `unicorn/require-array-sort-compare` off **only in the typed config**, so JS / `typeChecked: false` still catch `[2, 10].sort()`; don't put it in `DUPLICATED_RULES` (a test asserts none of those are enabled anywhere).
- **Autofix that breaks compilation**: with default options `import-x/no-duplicates` merged value specifiers into an `import type {}` and `consistent-type-imports` wrote `import type { type A, B }` (TS2206/TS1361). Use `import-x/no-duplicates` `{ "prefer-inline": true }`, `consistent-type-imports` `{ fixStyle: "inline-type-imports" }` and `no-import-type-side-effects`. Test with `new ESLint({ fix: true })` on a typed fixture and assert `result.output`.
- **react-doctor** duplicates ESLint (plugins `eslint`, `typescript`, `react-hooks-js`, `knip`; jsx-a11y names; react-you-might-not-need-an-effect names; size/complexity), scans `.html`/workflow files, and `react-hooks-js` misreads `useCases`/`use…` methods as hooks; its `todo` rule reports unsupported compiler syntax (`try/finally`). Run it with `--json --json-out <tmp>` and filter/print in golfo-lint. Source-aware filters (pass a cached `readSource(relativePath)` from the command): `no-fetch-response-used-without-status-check` is valid when the body is read first and `<response>.ok`/`.status` is checked in the next lines (find the variable from `X = await fetch(` with `indexOf`, not an unanchored regex — sonarjs flags it super-linear); `raw-sql-injection-risk` reports one `sql.raw` per file, so drop it only when **every** `sql.raw(...)` in the file takes a proven literal — parse with the TypeScript AST and follow `const` declarations and relative/`@/` imports to a string literal; names (`UPPER_CASE`) or regex matching are not proof. `button-has-type` "invalid type" for `type={CONST}`: drop only in `.tsx` (TypeScript checks it; JSX in JS still reports).
- **react-doctor rule internals**: before filtering a react-doctor rule, read its implementation in the consumer's `node_modules/.pnpm/oxlint-plugin-react-doctor@<v>/node_modules/oxlint-plugin-react-doctor/dist/index.js` (minified; find `id:\`<rule>\`` with Python and print a window). It shows what the rule already accepts, so the filter only covers the gap (e.g. `no-set-state-after-await-in-effect` accepts cleanup-flipped flags but not `signal.aborted` nor a flag `||` a call; `no-loading-flag-reset-outside-finally` does see `finally` and reports a guarded reset it cannot prove is an ownership check). Shared helpers live in `src/react-doctor/source-scope.js` (lexical `findDeclaration`, `listReferences`) and `project-modules.js` (imports, `findCallAt` for line:column, 1-based). Filters added: constant `sql.raw` through ternaries/templates/typed params; effect cancellation dataflow; `finally` reset independent of try/catch writes; own `useState` setter traced through same-file hooks; `Promise<void>` methods for `effect-needs-cleanup`. Excluded as undecidable advice: `no-layout-property-animation`, `no-array-index-as-key` (no preset duplicate exists), `no-locale-format-in-render`.
- **Keep reporting when the rule's claim is literally true** even if a reviewer called it a FP: `motion-animate-presence-must-outlive-child` on a keyed swap boundary still loses the exit on removal (a "keyed child" filter would also hide the modal case it targets); `no-create-object-url-without-revoke` when some path keeps blob URLs alive; `no-fetch-response-used-without-status-check` when the body is only schema-validated (a schema does not prove it models errors).
- **dependency-cruiser + TypeScript 7**: it resolves the project's `typescript` and skips all `.ts` files. Fix: spawn it with `node --import <hook>`; the hook uses `module.registerHooks` and returns `{ url, shortCircuit: true }` resolved with `createRequire(import.meta.url).resolve` — for `require()` Node ignores a changed `parentURL` passed to `nextResolve`. Needs Node ≥ 22.15.
- **actionlint + `background`/`wait`/`wait-all`/`cancel`/`parallel`**: rewrite the workflow keeping every line (comment `background`, `wait*`/`cancel` → `run: "true"`, dedent `parallel` groups and record column shifts), lint via `-stdin-filename <path> -format '{{json .}}' -`, shift columns back. Only rewrite keys of real steps: list items under a `steps:` key (also indentless `- ` at the `steps:` column, and `steps: # comment`), skipping block-scalar bodies (`run: |`) and other lists (`strategy.matrix.include`). When `background: true` opens a step (`- background: true`), replace it with a key the step lacks (`name`, `continue-on-error`, `timeout-minutes`, `shell`) to avoid duplicate keys; comment `wait:` lists also when their items sit at the key's column.
- **dependency-cruiser `not-to-dev-dep`**: MSW handlers in `mocks/`, `__mocks__/`, `dev-mocks/` load only in development behind a `NODE_ENV` check → exclude those folders from production code.
- **gitleaks on `.golfo/skill-coverage/*.json`** (16-hex content hashes next to `TOKEN`/`Linked` keys): allowlist needs `targetRules` for `condition = "AND"` to apply; a global allowlist silently ORs and hides real tokens. Test both: hashes pass, a real token in the same folder fails.
- **knip**: setting `entry` replaces knip's defaults; add only defaults that exist and only the Next built-ins actually imported, or knip prints configuration hints (noise). The shared config adds, when present: `scripts/**` (run by path), `.golfo-rp/*.{js,cjs,mjs}` (vercel `ignoreCommand`), `open-next.config.ts`, and passes every root `playwright*.config.*` to the Playwright plugin (`playwright: { config: [...] }`); a project `entry` is appended, not substituted. Truly project-specific entry points (files bundled/spawned by path from tests, `--import` preloads), OS binaries (`xdotool`) and deliberate direct deps resolved at bundle time (`pg-cloudflare`) belong in the consumer's `knip.config.js` via `createKnipConfig({ entry, ignoreBinaries, ignoreDependencies })`.
- **CLI arguments**: a subcommand that receives only options (`golfo-lint styles --fix`) must still append its default inputs; replacing them made Stylelint read stdin ("Empty source"). Treat args as inputs only when some arg does not start with `-`.
- **SonarJS is a curated list, not `recommended`** (`SONARJS_RULES` in the preset, plus `cognitive-complexity`; `sonarjs/aws-*` only with `awsCdk`). Admit a sonarjs rule only if it found a real defect on a consumer and is not: a spelling choice (`concise-regex`, `prefer-regexp-exec`, `single-char-*`, `no-redundant-optional`, `no-undefined-argument`), a typed rule that TypeScript already covers (`argument-type`; JS plugins get no types under oxlint), a security hotspot (`sql-queries`), test ordering (`hooks-before-test-cases`), or flagging valid patterns (`public-static-readonly` on a reassigned static, `no-skipped-tests` on Playwright `test.skip(condition)`). With a curated list, drop now-unused sonarjs entries from `DUPLICATED_RULES`/`NON_DEFECT_RULES`/stylistic lists instead of keeping dead `off`s.
- **Turned off after evaluating on TuTribu** (`NON_DEFECT_RULES`): `@typescript-eslint/prefer-nullish-coalescing` (intentional `||` fallbacks on `""`/`0`; on objects `||`≡`??`), `vitest/no-conditional-expect` (per-case assertions), `no-control-regex` (patterns that reject control chars), `unicorn/prefer-event-target` (pg/stream doubles need `EventEmitter`). Relaxed only in tests: `@typescript-eslint/max-params`, `sonarjs/cognitive-complexity`, `no-base-to-string`, `only-throw-error`, `preserve-caught-error` (cause dropped on purpose to keep private data out of output), `unicorn/prefer-dom-node-text-content` (Playwright `locator.innerText()`). `vitest/valid-expect` gets `maxArgs: 2` (Vitest's `expect(value, message)`); `id-length` gets `exceptionPatterns: ["^[A-Z]$"]` (oxlint checks type parameters, ESLint does not).
- Other ESLint rules turned off as FP-prone: `no-promise-executor-return` (`setTimeout(resolve)` shorthand), `no-unmodified-loop-condition` (flags set by async paths), `@typescript-eslint/unbound-method` (bound router methods), `no-dynamic-delete`, `no-invalid-void-type`; `no-misused-promises` with `checksVoidReturn.attributes: false`; in TS files `sonarjs/no-extra-arguments` and `sonarjs/different-types-comparison`.
- **React tuning (`REACT_TUNING`, every reviewed report was correct code)**: `react-you-might-not-need-an-effect/no-event-handler` and `no-pass-data-to-parent` (effects that sync the URL, an external store with cleanup, the clock, or move focus after a render; it even flags a `.some()` callback as passing data), `jsx-a11y-x/no-autofocus` (focus moved to the next step when the opening control disappears), `unicorn/no-document-cookie` (Cookie Store needs Safari 18.4 / Firefox 140). `no-noninteractive-tabindex` also accepts `role="region"` (scrollable regions must be focusable, WCAG 2.1.1). Keep the rest of the effects plugin (`no-derived-state`, `no-chain-state-updates`, ...).
- `@typescript-eslint/no-unused-vars` needs `ignoreRestSiblings: true`, `argsIgnorePattern: "^_"`, `destructuredArrayIgnorePattern: "^_"`: with defaults, every `const { secret: _secret, ...rest }` is reported and code silences it with `void name;`, which `no-meaningless-void-operator` then rejects.
- Dot-prefixed tool configs (`.dependency-cruiser.mjs`, `.prettierrc.mjs`) belong in the config-file globs (`**/.*.{js,mjs,cjs,ts,mts,cts}`) so `unicorn/no-top-level-side-effects` stays off there.

## Test golfo-lint changes against the consumer before releasing

- ESLint: temporary `eslint.dev.config.mjs` in the consumer worktree importing `file:///C:/.../golfo-lint-worktrees/<slug>/src/eslint/index.js`; run `pnpm exec eslint -c eslint.dev.config.mjs <files>` on the sampled files first (seconds), the full repo in background last. Delete the file before committing the consumer.
- CLI subcommands: from the consumer, `node C:/.../golfo-lint-worktrees/<slug>/bin/golfo-lint.js <cmd>` (tools resolve from the worktree's node_modules).
- To verify a filter, compare the original rule on a small fixture (e.g. a throwaway script running ESLint with only the upstream rule) against the wrapped one: the fixture must show the original reports and only the real one surviving.
