# golfo-lint adoption pitfalls

Known traps found while adopting golfo-lint, grouped as they were found. Read the whole file before the inventory (step 4) and again before dispatching fix batches (step 7) or touching CI (step 8): several of them decide how a batch is split, validated or committed.

- **Never run the full test suite while subagents edit the same worktree**: failures come from half-applied edits, not from your change. To attribute a failure, rerun only the failing files on the primary checkout (`main`) and on the branch once edits settle.
- **Source-reading filters in golfo-lint must resolve real bindings, not names or text**: when a filter drops a finding because the code is safe (constant `sql.raw` argument, `response.ok` checked later), parse with the bundled `typescript` (`ts.createSourceFile`) and follow the actual binding: lexical scope (parameters/locals shadow module constants), `const` only, objects only if read-only (`as const`/`Object.freeze`) and never written, imports followed through relative and `@/` paths, same function for the status check. Regex/name heuristics get reopened by review every round.
- **ESLint crash "Fix objects must not be overlapped"** names the culprit rule and aborts the whole run. Rerun with `--rule '<rule>: off'` to get the inventory; fix it in the preset.
- **Silent empty analyses**: always read the tool's own coverage line (dependency-cruiser "N modules cruised"; knip "Configuration hints"; jscpd file counts per format). A handful of modules on a TS repo means the check did not run.
- **In git-bash, call `node.exe`, not `node`, for scripts whose output you capture**: `node` can resolve to a winpty wrapper that prints only "stdin is not a tty" when stdout is redirected, so the run looks empty or failed.
- **Native tools get `/tmp/...` literally from git-bash** and write to `C:\tmp`: pass `C:/Users/...` paths (or `cygpath -w`) to `node`/`eslint -o`/`python`.
- `golfo-lint secrets` exits 3 without gitleaks: install it (`winget install --id Gitleaks.Gitleaks --version <pinned>`; add `$LOCALAPPDATA/Microsoft/WinGet/Links` to PATH in the same shell).
- **gitleaks scans git history in CI**: a test that writes a secret-looking fixture literal (e.g. a key containing `linkedin` next to a hex hash) fails CI even after you change the file. Build the triggering string at run time (`["…Linked", "Invitations"].join("")`) and add the old commit's fingerprint to `.gitleaksignore` with a comment. Run `golfo-lint secrets` *after* committing — before the commit, history does not contain the line.
- **Stylelint `--fix` may report "fixable" yet change nothing** (SCSS deprecations like `clip`): fix by hand (`clip: rect(…)` → `clip-path: inset(50%)`, dropping it when `clip-path` is already there; `word-break: break-word` → `overflow-wrap: anywhere`).
- **`no-unnecessary-condition` on runtime guards of stored data is often a false positive**: discriminator checks (`policy.mode` in a closed union, `request.source`, `scope.purpose`) protect against obsolete DB values; tests like "should close an invalid policy discriminator" fail if removed. Keep the guard and report it. Annotating `const row: T | undefined = rows[0]` does not help: TS narrows a union-declared local to the assigned type; only a parameter type or a non-union type survives.
- **`pgTable` object → array migration can collapse mutually-referencing tables to `any`** in typed ESLint (order-dependent circular inference) even when `tsc` passes, producing dozens of `no-unsafe-*`. Check the typed lint after converting; if it happens, keep the object form and report it.
- **`no-unnecessary-type-parameters` on `<Input extends X>(input: Input)`** usually exists to disable excess-property checks so tests can pass owner facts with extra private fields. Make the production signature honest (`input: X`) and move the generic into a test-only identity helper `function withPrivateFields<const Fact extends X>(fact: Fact): Fact { return fact; }` wrapping each call's argument (TS AST codemod): the type parameter is used twice, so the rule is satisfied, and `const` keeps literal discriminants.
- **Never dodge a rule with an equivalent spelling** (a callback ref instead of `autoFocus`, a `sleep()` helper around `page.waitForTimeout`, a `role` that only silences jsx-a11y): if the flagged code is correct and the rule cannot tell, turn the rule off in the preset with the reason; if it is not, fix the code. When neither is clear (a design change, a test that cannot run locally), ask the user with options instead of hiding the finding.
- **jsx-a11y per-role options only see an explicit `role`**: `no-noninteractive-element-interactions` `{ region: [...] }` does not cover `<section aria-label>`. For Escape delegated from a landmark, move the listener to `window` in an effect (`useEffectEvent` for the callback) and check `frame.contains(event.target)`: `window` runs after React's root dispatch, so `defaultPrevented` from inner handlers is still honored.
- **Normalize line endings after every subagent batch**: Windows edits leave CRLF in files the repo stores as LF, turning small edits into whole-file diffs. `git ls-files --eol | grep 'i/lf.*w/crlf' | awk '{print $NF}' | xargs sed -i 's/\r$//'`, and the same for new untracked files, before reviewing the diff.
- **Refactors that cross file lists go to one agent with the whole call graph**: `max-params` on constructors/interfaces needs every caller (setup/composition, fixtures, tests) changed together; give one subagent the finding list plus explicit permission to edit callers anywhere except files other agents own, instead of letting list-bound agents skip them.
- **Scripted refactors**: when slicing a function with `s[i:s.index('\n  }\n', i)+4]`, the slice ends in `\n  }` without newline, so a later `rindex('  }\n')` hits an inner block and silently drops the tail. Re-run `tsc` after every scripted batch.
- **Partial staging from git-bash**: `git add -p` fed by a heredoc mis-selects hunks. To commit only some lines of a file (e.g. scripts but not new deps in `package.json`), write the wanted content from `git show HEAD:<file>` + `sed`, then `git update-index --cacheinfo 100644,$(git hash-object -w "$(cygpath -w <tmpfile>)"),<file>` — `git hash-object` is native and needs a Windows path.
- **Swapping the consumer's type checker (e.g. `tsc` → `bun check`)**: first update the tool to its latest release (`gh api repos/<org>/<repo>/releases --jq '.[0:3][].tag_name'`, then `bun upgrade`) — benchmarking an old version gives the wrong verdict. Measure 3 runs per case on the same code and report a table; a single slow run is not "cold start" until repeated. Then prove parity before switching — same file count (`tsc --listFilesOnly | grep -v node_modules | wc -l` vs the checker's "N files"), the same error on an injected bad file, timing. Then pin the tool (`.bun-version` + `oven-sh/setup-bun` by SHA in the shared CI setup action), update README/AGENTS/docs, and keep `typescript` for the editor, `next build` and golfo-lint's typed ESLint.
- **oxlint `react(purity)` flags `Date.now()` even inside an event handler declared in the component body** (often introduced by the `prefer-date-now` autofix). Move the call into a module-level helper (`function readCurrentTimeMs(): number { return Date.now(); }`) with a one-line JSDoc saying why; do not disable the rule.
- **Evaluating a faster runner or formatter**: present measured findings and a recommendation, then wait — the user decides. Current decisions: `bun check` and `bun lint` adopted, `bun fmt` declined (do not re-propose unless asked). When a tool is only in canary but the user says the stable release is imminent, adopt the canary and pin the stable version once it ships.
- **Evaluating a faster linter runner (e.g. `bun lint`) for the preset**: run `<runner> lint --doctor --config <eslint config>` first. It prints which rules run natively vs in JavaScript and whether typed custom rules (`golfo-lint/no-unnecessary-condition` needs type info) can run; then compare per-rule counts against an ESLint JSON run on the same tree before recommending it. A repo with `.oxlintrc.json` and `eslint.config.*` makes such runners pick the oxlint config unless `--config` is passed.
- **Vitest workers die with `exit code 3221225794` (0xC0000142) on Windows** when several subagents run typed ESLint/Vitest at once: the run reports "N passed" plus "Errors" and silently skips files. Rerun the related files with `--maxWorkers=2 --reporter=json --outputFile=<C:/... path>` in background and check `testResults` length equals the file count.
- **Known consumer false positives to report, not contort**: `unicorn/prefer-simple-sort-comparator` on string fields (its `b - a` suggestion is invalid for ISO strings), `@typescript-eslint/no-misused-promises` on pg `onConnect: async` (pg awaits it; `@types/pg` says void), `promise/catch-or-return` on `.then().catch().finally()`. For `no-unnecessary-type-conversion`/`boolean-literal-compare` on `rows[0]` facts, prefer `rows.at(0)` (honest `T | undefined`) over removing the guard; for Radix `Switch` `checked === true` → `checked` is safe (always boolean).
- **Ambiguous "re-enable the rules you turned off"**: list the two groups with counts and ask — rules turned off in the preset as duplicates/false positives (re-enabling brings that noise back) vs. the consumer's pending-adoption list (re-enabling adds every finding to fix). Never assume a rule was turned off only for speed without checking its comment.
- **Porting `no-restricted-imports` (or any rule with options) from `.oxlintrc.json` overrides to flat config**: flat config replaces a rule's options per matching block, it never merges them, so an override that adds one pattern for some folder silently drops the global bans there. Rebuild the full chain: shared pattern constants (global bans, extra `group` + `regex` entries for layers), one block per override that spreads the shared list plus its own entries, and a JSDoc saying options are repeated on purpose. Diff every old `files` block against the new config before deleting `.oxlintrc.json`, then prove it with throwaway probe files (one forbidden import per pattern, in each overridden folder): `golfo-lint lint` must report exactly the probes, then delete them.
- **Consumer CHANGELOG**: when the adoption changes anything a user can perceive (focus/keyboard/screen-reader behavior of a control, an interaction moved to a shared component), add the Spanish `[Unreleased]` entry in the same PR; Codex flags its absence when the repo's AGENTS.md requires it.
- **dependency-cruiser rejects regexes its safe-regex check considers unsafe** ("has an unsafe regular expression. Bailing out" — the whole analysis stops): avoid nested optional groups followed by open classes like `([^/]+/)?setup\.[^/]+$`; use flat alternations (`(setup|[^/]+/setup)[.][a-z]+$`) and run `golfo-lint architecture` on the consumer after adding a rule.
- **knip runs on golfo-lint itself in `golfo-lint all`**: a JSDoc type import from an undeclared package (`import("estree").Comment`) fails CI as an unlisted dependency. Type through a declared one (`ReturnType<import("eslint").SourceCode["getAllComments"]>[number]`) and run `node bin/golfo-lint.js all` before pushing, not only `npm run ci`.
- **Enabling the pending analyses (follow-up to option a)**: one branch and worktree per analysis from `origin/main`, subagents in parallel (duplicates split by folder `app/` / `src/` / rest on one shared worktree). Each PR appends its analysis to the CI loop; they all conflict on that line and on refactored files, so merge them one at a time, merging `main` into the next and rerunning `golfo-lint all` (refactors leave new in-file-only exports that only knip sees). The PR that makes the list complete switches the step to `pnpm exec golfo-lint all` and closes the tracking issue.
- **`golfo-lint duplicates` must exit 0 below the threshold**: jscpd's `--exit-code` fails on any clone regardless of `--threshold` (fixed in 0.3.1). If it fails while the report shows a total under 1%, check the flags before refactoring more.
- **react-doctor findings**: have one agent fix the real ones, then verify every claimed false positive yourself; several "false positives" (an AnimatePresence removed with its child, blob URLs a published message kept forever, a success body accepted with a 5xx) were real. Fix FPs in golfo-lint with AST filters that resolve bindings and fail closed; turn off only advice rules the tool cannot decide.
- **Big duplicates refactors in TuTribu**: before the PR, (1) compare every `.tsx/.ts` touched against `origin/main` with `oxc-transform-react` (`transform(f, code, {reactCompiler:{}})`, count `$[0]`): pulling an inline `(await x).find(cb)` out of an async page removes the compiler's bailout and the page gets `useMemoCache`, breaking tests that call it as a function; (2) if `schema.ts` changed, compare `getTableConfig` of every `PgTable` against the main version in a throwaway Vitest probe (`drizzle-kit export` crashes on `sql` defaults with params).
- jscpd flags identical `import` blocks; golfo-lint 0.3.2 skips them with `--ignore-pattern`, so never reorder imports to dodge a clone.
- `server-only`/`client-only` unlisted in a Next.js repo is NOT a defect (Next resolves them; its docs make installing optional) — golfo-lint's knip config ignores them when imported.
